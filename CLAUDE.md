# Repo rules for Claude

This repo is public and served at <https://nurmdabd.github.io/study-notes/> (GitHub Pages, from `main`, root folder).

- **Share copies only.** The PDFs here are the print-locked share copies (`*-pack_share.pdf`, and `*-pack_Bangla_share.pdf` for a Bangla pack) from `nurmdabd/academic-material`. Never add a screen copy, a print copy, sources, `.tex` or figures. Their names here (`<short>-<session>-pack.pdf`, `…-pack-Bangla.pdf`) leave out "share" on purpose; the user chose to keep them (2026-10-20).
- **Publish with the tool:** `python3 tools/publish.py ../academic-material` (the repos cloned side by side; in a cloud session they are under `/home/user/`) copies every pack's share copy and rewrites `items` in `catalogue.json`. A Bangla pack becomes its own item, ID `<code>-<session>-pack-bn`, "Exam pack (Bangla)", right after the English one. Do not edit `items` by hand. After publishing, run the tests below and tell the user which new items to tick on the admin page. A new subject goes into `subjects` first (folder, code, short name, title, `offerings`).
- **Subjects: departments, semesters and both codes.** Each subject in `catalogue.json` → `subjects` has `offerings`: one entry per department, semester and syllabus, `{"dept": "EEE", "semester": "3-2", "code": "EEE 0714 3229", "syllabus": "new"}` (and the `old` one; add `"title"` when that syllabus names it differently). Take them from `academic-material/curriculum/<DEPT>/courses.json`, never from memory; a subject taught in two departments gets entries for each. `code` (the old code without the space, `EEE329`) stays the subject's key for hidden items, the order and orders, so never change it. The page shows Department and Semester chips (All by default, a subject shows when one of its entries matches both), both codes and the semester on each subject, and a Sort menu (suggested = the admin's `subject_order`, name, code, semester); the filters and a chosen sort go into the link (`?dept=EEE&sem=3-2&sort=name`). The admin page sets `default_sort`, the order visitors see first (Code.gs with it deployed 2026-10-22); its Sort buttons (by code, by title, newest paper first, papers newest year first) only rearrange the admin list, which becomes `subject_order` / `item_order` on Save.
- **`catalogue.json` → `site`** holds the WhatsApp number, `report_form` (the "Report a mistake" Google Form: a flag icon on each pack row, a top-bar button and a footer link; removing the key hides them all) and `order_endpoint` (the Apps Script web app URL). Its price note and options are only the first values of the sheet's **Settings** tab and the fallback when the web app does not answer; the live prices and options are set on `admin.html` with the admin key and reach the page through `settings.json` (or, without it, the web app's `?action=settings`). Options are names or `{name, available, price}`.
- **Publishing never touches the admin settings** (they live in the user's sheet). Hidden packs, subject order and paper order are keyed by subject code and pack ID (`<code>-<session>-pack`), so keep IDs stable: a new subject or a new paper stays hidden (not in `known_subjects` / `known_items`) until the user ticks and saves it on the admin page (it shows there with a New badge), so tell them what you published.
- **`settings.json`** is written by the Apps Script (with the user's `GITHUB_TOKEN`) on every admin save and by the hourly sync; the page reads it first, and only asks the slower web app when it is missing. Never edit it by hand: the sheet's Settings tab is the source.
- **`apps-script/Code.gs`** lives in the user's Google Sheet; this file is its source copy. After changing it, tell the user to paste it again and redeploy with **Manage deployments → New version** (same URL). See `SETUP.md`.
- **Test the script** with `node tests/apps-script.test.js` (a mock of the Google services; extend it for new behaviour) before handing it over (the user pastes and redeploys it by hand, so a bug costs a round), and after every publish (it reads `catalogue.json`). The page and the admin page: in a browser, with the web app mocked. On the laptop: Playwright's Chromium in `~/.venvs/browser`; serve this folder with `python3 -m http.server`, route `https://script.google.com/**` (and `https://gc.zgo.at/**`, so tests are not counted) to stubs, screenshot at 1280 and 390 px, light and dark, and collect console errors.
- **Visit counts:** GoatCounter (`nurmdabd-notes.goatcounter.com`, no cookies) on `index.html` only, never `admin.html`. Events through `track()`: `download/<pack id>`, `print/<pack id>`, `report/<pack id>`, `report/top-bar`, `report/footer`; keep these names stable, they are the dashboard's rows. The footer says visits are counted anonymously. Shared links may carry `?ref=<tag>` (Campaigns).
- Pushing to `main` publishes the site, and the user has agreed to that for this repo. Check the page (`index.html`) in a browser before pushing a change to it.
